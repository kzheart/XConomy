# 木兰 PG 钱包与商城验收（2026-10-02）

版本 XConomy 2.26.3-mulan.3，核心提交 d97260e；目标 Paper 1.21.1 / Java 21。使用木兰原 Spawn、Lobby 两个独立游戏进程（同一物理主机）、原 Velocity 和真实 PG，没有额外创建测试服。下列为整套商城/经济组合测量，不能归因于某一项修改；不是跨物理机网络分区测试。

跨服累计 11,065 笔订单，10,963 DELIVERED、102 FAILED；100 个测试账户金币、限购与奖励对账无差异。双服商品只扣 PG 金币；等级和点券不能据此视作统一共享钱包。

最终商城四货币组合另采用本地修复版 PlayerPoints 3.3.5-mulan.1。100 人 600 秒阶段：30,003/30,003 成交，P95 305.221 ms，Spark 5 秒 TPS 采样最低 20，10 秒窗口 Tick P95 最大 38.3 ms；100 笔注入第四货币扣费失败完整退款。再运行 100 人每 4 秒诊断，共 3,300/3,300 成交。最终 33,403 订单中 33,303 DELIVERED、100 FAILED，四币、奖励、点券数据库与玩家等级文件对账无差异。

原 PlayerPoints 3.3.5 在首轮四货币对账出现 7 个测试账户多出 10–30；源码有待写队列交接遗漏和提交期间余额可见性的竞态。修复后重新运行上述 600 秒，失败证据保留，没有将旧轮标为通过。该点券修复沿用每服独立 SQLite，不新增其 PG 后端；GPL 源码与补丁在用户工作区木兰/PlayerPoints，并已归档完整源码。

相同 120 秒 / 100 人每 4 秒 JFR 诊断：基线主线程 XConomy SQLite 样本 77，奖励后立即保存归属 FileWrite 6,000 次/17,555 ms；最终主线程 SQLite 样本 0、PG QueryExecutor 样本 0，合并玩家保存 FileWrite 3,000 次/8,791.762 ms。采样未观察到不证明所有冷路径完全没有阻塞。

## 检查与迁移

- Core 7 项 JUnit 在真实 PG 全部通过，未跳过；包括有序队列、异常拒绝、方言、原子并发扣款、小数加减、绝对设置及交易日志异常回滚。
- 未提供 XCONOMY_TEST_PG_URL 的本地构建会跳过实库部分，不能以此声称 PG 验证通过。
- Spawn 原 SQLite 210 账户停写迁移至 PG，UID/名称/余额/隐藏状态逐项核对。Lobby 原 SQLite 全 0，只导入 PG 中不存在的账户。
- 两节点正式产物 SHA-256：`2a17852f0bea2e92f6da95656473b57b654ceb0535fea59a2dc320099dc67f47`。
- 验收后两服人数上限恢复 20，测试商品/探针移除，101 测试账户清零并注销，原非测试金币与点券不变。PG 配置继续使用；原插件、原 SQLite、失败与通过阶段备份均保留。

## 边界

共享原子核验针对 PG 玩家钱包。普通 Vault 同步接口与原生命令可能等待 PG；非玩家账户、银行、跨两账户转账和跨多货币/订单事务不因此变为统一原子提交。在线缓存用于展示，扣款以 PG 行锁内的已提交余额为准。

数据库队列不是耐久日志，强杀、断电或提交结果未知不承诺 exactly-once 与自动恢复；未知钱包结果由商城留作人工核查。第三方点券后台故障须另行对账。玩家文件合并保存正常约 5 秒，强杀可能回档。正常关闭/切服排空已测，故障网络分区与强杀恢复未测。

完整账务/性能报告位于用户工作区 `木兰/MulanShop/docs/load-test-optimized-20261002.md`；服务端证据统一在既有运维归档目录，不包含数据库凭据的源码提交。
